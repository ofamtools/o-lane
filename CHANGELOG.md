# Changelog

## Unreleased

- Added: the lane's `parent` prop is a reference to a lane and its `task` prop a reference to the host's `task` (`hostNoun`), so ochazuke's relation graph follows them (a mounted mtm reads `lane.task` as a reference to mtm's task; a key that names nothing stays as written). `project`, `repo`, `branch` and `worktree` stay plain strings: they are stored as names or paths, not as the target noun's key. Requires ochazuke v0.114.0 (`hostNoun`); the family word list copy is refreshed.
- Added: setting `history.keep` (default 200, `0` keeps everything) bounds the undo history (`.history/`): the write that adds an entry removes all but the newest N (names only, never entry contents; oldest first, so an interrupted pass resumes), numbering never resets, and undo past the retained range reports `nothing more to undo: older changes were removed by history.keep`. Daily backups already pruned to `backup.keep` (test `TestStoreBackups`); they now share one retention function with history.
- Added: a lane's `project` is stored as the id of the host's project (mtm's key) when its name, id or `mtm:<id>` matches exactly one project, and is typed as a reference to the host's `project` (`hostNoun`), so lanes hang under the project in the relation graph. The name is kept in the new `project_label` field and is what every list, filter, grouping and detail shows (the host's name for the id, else the kept name, else the stored value). Typing a name keeps working everywhere (`--project`, `project=`, define, plan define, MCP, associate); a name matching nothing or several projects is stored as typed. JSON: `project` is the id, `effective_project` still the name, new `effective_project_id` and `project_label`; page rows keep `project` as the name with `project_id` beside it. With no host projects (`lanes.project-source` none or no mtm) nothing is rewritten.
- Added: `project resolve [--dry-run]` (owner only) rewrites the stored references that name exactly one host project as that project's id, keeping the name in `project_label`; unmatched and ambiguous names and lanes without a project stay byte for byte; history entries are not read. A real run first copies `roots/` to `<data>.bak-<date>-project-ids` (and writes nothing if that fails) and is idempotent.

## v0.5.0

- Changed: requires ochazuke v0.110.1 (esc only leaves insert in modals and `q` closes them; label-first pickers).
- Changed: the pane variables are read as `MTM_X` first, then `TUIOS_X` (mtm sets both for one release): `ENV`, `SESSION`, `PANE_ID`, `HARNESS`, `AGENT_NAME`, through one `paneEnv` helper.

## v0.3.1 (2026-11-08)

- Changed: the Lanes page draws a whole row in its status tone (every cell, as per-cell tones so the mounted mtm page draws them too), not only the status cell. Planned (no tone) rows stay default, archived rows keep their dim tone, the cursor highlight still wins, and live, stale and name tones still layer on top. Setting `lanes.status-tone-scope` = `row` (default) or `cell` (the old status-cell-only look); `lanes.status-tones` false still turns colour off.

## v0.3.0 (2026-11-08)

- Changed: every default status but `planned` has its own colour (the `tone` in `lanes.statuses`): planned none (default colour), running `state.working` (blue), parked `lane.parked` (orange), review `lane.review` (violet), merged `lane.merged` (teal, bold), done `state.done` (green), cancelled `lane.cancelled` (rose), archived `lane.archived` (muted, dim). merged and done no longer share a tone. The `lane.*` rows are declared with `Appearance.SetTone` (light and dark colours) and are overridden in `themes.json` `tones`, or by naming another tone in `lanes.statuses`; test `TestDefaultStatusTonesAreDistinct`. Existing `lanes.statuses` saved in settings.json keep their own tones.
- Added: a lane with unfinished work below it shows `done/total` after its status on the Lanes page (`3/5`; all descendants, archived ones excluded; done is a status with `ends: true`). Rows carry `children_done` and `children_total`. Setting `lanes.rollup-counts` (default true) turns it off.
- Added: `lane archive --finished-trees [--dry-run]` archives the root of every root tree whose lanes are all complete (`ends` or the archive role); a tree with one incomplete lane is untouched, descendants keep their statuses and are hidden with the root, restoring the root brings the tree back, one undo, nothing deleted. `--dry-run` lists the trees (`archived`, `kept`) and changes nothing.
- Changed: the "Tracking work (o-lane)" setup note (claude-md, codex-agents) tells agents to archive only whole finished trees with `mtm lane archive --finished-trees` (dry run first) and never to delete.

## v0.2.1 (2026-11-08)

- Fixed: the "Tracking work (o-lane)" setup notes (`setup.json` claude-md and codex-agents), the README and a verb help text told agents to run `mtm lane status done --id ID` and `mtm lane status`, which answer "command not found" (the short spelling reaches operations, not prop-shaped requests). They now give the one-call form `mtm lane set ID status=VALUE reason="..."`; the test asserts the old spelling is absent.

## v0.2.0 (2026-11-08)

  - The lifecycle status is the writable `status` prop of lane: `lane status done --id ID`, `lane set ID status done`, MCP `lane.lane.set {prop: status, value}`. The reason is the writable `reason` prop, so one multi-prop set carries both: `lane set ID status=review reason="branch X"` (one write, one history entry; `reason` alone appends a note); `lane status review --id ID` needs none, and `park`, `finish`, `cancel` keep `--note`.
  - `lane state --from-tag TAG` is `lane tag TAG [--note]` (the `lanes.tag-statuses` table maps the tag; an unmapped tag appends a note). `lane copy` is `lane duplicate` (alias `dup`). `lane note` is `lane annotate`. `lane choose-state` is `lane choose-status` (the Lanes page `s` row). `focus-pane` stays: the compound name is judged as a whole and ochazuke's `focus.to` focuses a component, not a tuios pane.

  - The "Tracking work (o-lane)" setup note names the new spellings: `lane.lane set` (the `status` prop), `lane.lane annotate`, `mtm lane status`, `mtm lane annotate`. `testdata/lexiconcheck.txt` is empty (it held the framework's 23 rows); `testdata/lexicon-words.tsv` is the family list (plus the row `lane-detail`).
