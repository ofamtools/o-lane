# Code map

- `main.go`: XDG data path, global `--data`, oden dispatch and ochazuke CLI mount.
- `pickers.go`: the lane, project and agent noun pickers (`PickerDef`), listed by the catalog.
- `app.go`: the verb-spec table (each row names its own `run` method and aliases), explicit app nouns, transport-bound actors, settings configuration and target reveal.
- `props.go`: framework standard typed `get`/`set` over the lane store, read-only filter props for prop filters and the default `open` and `stale` saved filters (kept in step with `lanes.statuses` by `configure`).
- `agents.go`: agent participants' derived live status from `lanes.agent-harnesses` rows (transcript templates, tail time field, idle, hook event map, payload fields), the incremental append-only hook log (`agent-events.jsonl`), the lazy per-refresh agent reader, `agent-hook` (bounded, lock-free, exit 0) and `agent list` rows.
- `setup.go`, `setup.json`: o-lane's declarative integrations for ochazuke's shared setup verbs; the Claude Code SubagentStart/SubagentStop hook items.
- `agents_test.go`, `testdata/agents/`: agent association round trip, fixed-clock working/idle/done/missing statuses, captured Claude Code hook payloads (copied from an earlier pane server), stuck-stdin bound, and setup install/idempotence/backup/plan/uninstall against a temp settings.json that already has another tool's hooks; the `lanes/agent-working` story uses the fixture transcript.
- `filter.go`, `filter_test.go`: shared `--status` parsing and validation, the tree rule (matches plus ancestors) used by `lane tree`/`lane rows`/`lanes.status-filter`, and row values that make every filter prop present; tests cover CLI `--status`, the setting, page prop filters, saved filters and a skipped hidden-search-text test awaiting ochazuke `ListItem.Search`.
- `settings.go`: public defaults; lifecycle rows and configurable status presets, roles, links, watcher tags and later page/import/export declarations.
- `model.go`: specs, lanes, pane refs, links, actor-attributed history; derived lifecycle times, estimates and root rollup; status descriptions and the status reason (`statusReason`, `statusAbout`).
- `verbs.go`: the per-row `run*` handlers, the shared call setup (`App.handler`) and the one relation handler behind the four `associate`/`unassociate` rows. `lane.choose-status` is an alias of `lane.status`; `lane.choose-pane` stays its own row because its pane argument is a pane-choice ID.
- `actor.go`, `actor_test.go`: ordered harness detector rows (Codex, Claude Code, omp via PI session variables), explicit harness-scoped run IDs, injected-env and history/undo isolation checks, per-run identity, the single framework override and store policy fallback derived from the verb-spec rows. Writes are open; only the soft-delete row declares never, without Destructive. App calls honour framework rights overrides.
- `keys.go`: unknown-key did-you-mean (edit distance) over a struct's JSON fields.
- `record_first_test.go`: define's lifecycle props and unknown-key notice, missing parent / empty name / empty note, reopen restore and reason alone.
- `plan.go`: Goldmark table parsing, validated configurable column aliases, shared JSON/plan definition handler (unknown JSON keys named in a notice), exact plan relation queries and read-only directory checks.
- `plan_test.go`, `testdata/plans/`: three copied table variants and golden specs; CLI/MCP rights, idempotency, source preservation and dry-run isolation regressions.
- `project.go`, `project_test.go`: project references (optional host kind, kind-less matching), nearest-ancestor inheritance, the shared project association handler, and the optional `lanes.project-source` listing/completion. Mounted calls use `cli.Host` with the host's full argv; standalone calls keep the injectable PATH runner. No project store; mtm is never required. `project_ids.go` caches the host's list (3 s; a failed read 30 s, single flight): reads (rows, lists, pages, drawing) use only the stored id and the lane's kept name and never call the host; a `--project` filter asks it only when no stored id or name matches; writes wait for the host. `live.go` builds one `paneTree` per read (children map, pane list) for subtree panes and pane holders.
- `changes.go`: atomic define/add (lifecycle props through the set patch; missing parent saved at the top level; empty name `untitled-STAMP`), domain mutations, status presets (`lanes.restore-presets` restore the open status before closing), shared association handler (moving a pane off its other lanes unless `lanes.pane-one-lane` is off), cycle refusal and undoable subtree delete.
- `store.go`: process lock, per-root documents, transaction recovery, snapshots and actor-safe undo with append-only audit receipts.
- `atomic.go`: private synced temporary writes, rename and directory sync (adapted from o-questions).
- `rollup.go`: subtree `done/total` counts (`rollups`) and `lane archive --finished-trees` (`finishedRoots`, `ArchiveFinished`); `rollup_test.go` covers it and the distinct default status tones (`statusTones` in `settings.go`).
- `backup.go`: daily private tar/gzip archives and retention (adapted from o-questions).
- `stale.go`, `stale_test.go`: read-only stale projection from lifecycle `starts` and current participants on each lane and descendants whose lifecycle rows have `starts:true`, conservative unknown evidence, activity metadata, CLI filter, saved/typed filters, opt-outs and timestamp checks; `lanes/stale`, `lanes/stale-off`, `lanes/stale-working-descendant` and `lanes/stale-needs-input` stories capture list/detail, opt-out, deep working descendants and waiting agents.
- `pane_prefix_test.go`: association/start/reverse-verb prefix canonicalization and record-first fallback, undo, legacy live-prefix matching, ambiguity, exact-ID priority, status-change timestamps and reader notifications when prefix uniqueness changes.
- `live.go`: one host/session-scoped unique-prefix resolver shared by association snapshots and live reads; validated data-driven live labels/tones/glyphs (including legacy string maps), explicit host/session snapshot batching with status-change timestamps, all-level subtree aggregation (a pane counts only for the lane holding its latest association, `paneHolder`), CLI read enrichment and cancellable argv focus. Role filters narrow aggregates while retaining pane details; all live status is derived.
- `live_reader.go`: incremental stdout through the existing injectable runner, bounded scanner/event/notification queues, mutex-protected snapshot cache, seq/boot reconnect, gap resync, replay ceiling, bounded backoff and cancellation; subscription events also notify lanes holding window prefixes when candidates change, including changes in uniqueness. Settings and framework objects stay on the UI loop.
- `live_test.go`, `testdata/live/` (stub `mtm`): aggregate/settings/snapshot/persistence tables, recorded gap/replay/close streams, boot-change and page-reader lifecycle regressions. A stub mtm executable on temporary PATH exercises the production runner without a daemon.
- `pane_json.go`, `pane_json_test.go`, `testdata/tuios/`: one array/object list decoder shared by pane discovery and live snapshots; normalized command captures cover both session/window shapes and `g p` focus to the recorded session/window.
- `app_test.go`, `cli_test.go`: isolated schema, per-verb CLI, published rights rows, attributed agent reword/delete-refusal coverage, actor and configurable-status checks.
- `store_test.go`: process concurrency, recovery, undo, cycle refusal, define atomicity and daily archives.
- `review_test.go`: V1–V7 regressions plus shared pane matching, effective finish times, subprocess pipe bounds, deleted history and legacy/crash-safe audit undo.
- `mcp_test.go`: generic framework stdio protocol, transport attribution, dry run, rights refusals and generated harness config.
- `page.go`: portable tree-page declaration, lifecycle/live word spans, live glyph tones and the name tone matching the status cell, derived duration/pane-role cells, detail sections (led by the status description section, `lanes.status-descriptions`), binding rows and chooser sources. Rows carry `doc` (newest link matching `lanes.doc-link-kinds`) and `pane` (first current working pane), including the no-argument mounted page source. Status and pane chooser entry points share existing domain handlers. The pane chooser discovers sessions/windows through the injectable runner and carries explicit session/window references.
- `tui.go`: standalone mount, asynchronous replacement row loads and optional refresh timer, reader lifetime/generation/cancellation and live settings projection, plus a cached read-only detail viewer. Rendering reads only cached rows; tree/field/detail layout and keys belong to ochazuke. CLI/smoke/catalog requests start no subscription.
- `pane_owner_test.go`: a pane moving between lanes (history, one undo, CLI `moved_from`), the read-time latest-lane rule on hand-made shared data, and `lanes.pane-one-lane=false`.
- `page_test.go`, `cmd/o-story/stories/lanes/*.json`: monogatari fixtures and the four L4, two L8, two project, a name-tone opt-out, two status-filter (`filter-status`, `status-filter-setting`), an agent (`agent-working`), an association-to-focus (`focus-pane`) and two status-description (`status-description`, `status-description-off`) stories, plus tree/catalog mounting, opt-outs, fixed-clock durations, ordering, pane chooser failures, focus and yank checks. Data and identity are isolated; every external command is fake.
- `peer_test.go`: portable and page-source doc selection, setting opt-out, working/current pane selection, and standalone/host project source behavior with temporary host argv and malformed-env checks. `app.go` declares the host-only `g s` peer row; the captured-catalog story and real notes-delivery walk live in the host consumer's verification.
- `Makefile`: bounded Go build/test and coordinator race gate.

The app owns domain status and persistence; released ochazuke owns the CLI, catalog, rights gate and UI. No family-library modifications or local module replacements are required.

Compared with Vim: domain operations have no Vim counterpart. Navigation/folding/search reuse ochazuke; the read-only viewer uses its scroll window with j/k, gg/G and ctrl+d/ctrl+u binding rows (eight-line half-page movement). See README for help tags and differences.

Mounted extension rows include live snapshots. Released ochazuke v0.72.1 has no persistent external page subscription hook; hosted reader lifetimes and per-run tones in Markdown detail require general framework capabilities. No app-specific daemon or host workaround is introduced.
