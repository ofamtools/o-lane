# Code map

- `main.go`: XDG data path, global `--data`, oden dispatch and ochazuke CLI mount.
- `app.go`: catalog verbs, explicit app nouns, shared relation dispatch, transport-bound actors, settings configuration and target reveal.
- `props.go`: framework standard typed `get`/`set` over the lane store, read-only filter props for prop filters and the default `open` and `stale` saved filters (kept in step with `lanes.states` by `configure`).
- `agents.go`: agent participants' derived live state from `lanes.agent-harnesses` rows (transcript templates, tail time field, idle, hook event map, payload fields), the incremental append-only hook log (`agent-events.jsonl`), the lazy per-refresh agent reader, `agent-hook` (bounded, lock-free, exit 0) and `agent list` rows.
- `setup.go`, `setup.json`: o-lane's declarative integrations for ochazuke's shared setup verbs; the Claude Code SubagentStart/SubagentStop hook items.
- `agents_test.go`, `testdata/agents/`: agent association round trip, fixed-clock working/idle/done/missing states, captured Claude Code hook payloads (copied from tuios), stuck-stdin bound, and setup install/idempotence/backup/plan/uninstall against a temp settings.json that already has tuios hooks; the `lanes/agent-working` story uses the fixture transcript.
- `filter.go`, `filter_test.go`: shared `--state` parsing and validation, the tree rule (matches plus ancestors) used by `lane tree`/`lane rows`/`lanes.state-filter`, and row values that make every filter prop present; tests cover CLI `--state`, the setting, page prop filters, saved filters and a skipped hidden-search-text test awaiting ochazuke `ListItem.Search`.
- `settings.go`: public defaults; lifecycle rows and configurable state presets, roles, links, watcher tags and later page/import/export declarations.
- `model.go`: specs, lanes, pane refs, links, actor-attributed history; derived lifecycle times, estimates and root rollup; state descriptions and the state reason (`stateReason`, `stateAbout`).
- `actor.go`, `actor_test.go`: ordered harness detector rows (Codex, Claude Code, omp via PI session variables), explicit harness-scoped run IDs, injected-env and history/undo isolation checks, per-run identity, the single framework override and store policy fallback; the app honours framework rights overrides.
- `plan.go`: Goldmark table parsing, validated configurable column aliases, shared JSON/plan definition handler, exact plan relation queries and read-only directory checks.
- `plan_test.go`, `testdata/plans/`: three copied table variants and golden specs; CLI/MCP rights, idempotency, source preservation and dry-run isolation regressions.
- `project.go`, `project_test.go`: project references (optional host kind, kind-less matching), nearest-ancestor inheritance, the shared project association handler, and the optional `lanes.project-source` listing/completion through the injectable runner. No project store; mtm is never required.
- `changes.go`: atomic define/add, domain mutations, state presets, shared association handler (moving a pane off its other lanes unless `lanes.pane-one-lane` is off), cycle refusal and undoable subtree delete.
- `store.go`: process lock, per-root documents, transaction recovery, snapshots and actor-safe undo with append-only audit receipts.
- `atomic.go`: private synced temporary writes, rename and directory sync (adapted from o-questions).
- `backup.go`: daily private tar/gzip archives and retention (adapted from o-questions).
- `stale.go`, `stale_test.go`: read-only stale projection from lifecycle `starts` and current participants on each lane and descendants whose lifecycle rows have `starts:true`, conservative unknown evidence, activity metadata, CLI filter, saved/typed filters, opt-outs and timestamp checks; `lanes/stale`, `lanes/stale-off`, `lanes/stale-working-descendant` and `lanes/stale-needs-input` stories capture list/detail, opt-out, deep working descendants and waiting agents.
- `pane_prefix_test.go`: association/start/reverse-verb prefix canonicalization and record-first fallback, undo, legacy live-prefix matching, ambiguity, exact-ID priority and state-change timestamps.
- `live.go`: one host/session-scoped unique-prefix resolver shared by association snapshots and live reads; validated data-driven live labels/tones/glyphs (including legacy string maps), explicit host/session snapshot batching with state-change timestamps, all-level subtree aggregation (a pane counts only for the lane holding its latest association, `paneHolder`), CLI read enrichment and cancellable argv focus. Role filters narrow aggregates while retaining pane details; all live state is derived.
- `live_reader.go`: incremental stdout through the existing injectable runner, bounded scanner/event/notification queues, mutex-protected snapshot cache, seq/boot reconnect, gap resync, replay ceiling, bounded backoff and cancellation; subscription events also notify lanes holding unique window prefixes. Settings and framework objects stay on the UI loop.
- `live_test.go`, `testdata/live/`: aggregate/settings/snapshot/persistence tables, recorded gap/replay/close streams, boot-change and page-reader lifecycle regressions. A stub tuios executable on temporary PATH exercises the production runner without a daemon.
- `tuios_json.go`, `tuios_json_test.go`, `testdata/tuios/`: one array/object list decoder shared by pane discovery and live snapshots; normalized command captures cover both session/window shapes and `g p` focus to the recorded session/window.
- `app_test.go`, `cli_test.go`: isolated schema, per-verb CLI, rights, actor and configurable-state checks.
- `store_test.go`: process concurrency, recovery, undo, cycle refusal, define atomicity and daily archives.
- `review_test.go`: V1–V7 regressions plus shared pane matching, effective finish times, subprocess pipe bounds, deleted history and legacy/crash-safe audit undo.
- `mcp_test.go`: generic framework stdio protocol, transport attribution, dry run, rights refusals and generated harness config.
- `page.go`: portable tree-page declaration, lifecycle/live word spans, live glyph tones and the name tone matching the state cell, derived duration/pane-role cells, detail sections (led by the state description section, `lanes.state-descriptions`), binding rows and chooser sources; state and pane chooser entry points share existing domain handlers. The pane chooser discovers sessions/windows through the injectable runner and carries explicit session/window references.
- `tui.go`: standalone mount, asynchronous replacement row loads and optional refresh timer, reader lifetime/generation/cancellation and live settings projection, plus a cached read-only detail viewer. Rendering reads only cached rows; tree/field/detail layout and keys belong to ochazuke. CLI/smoke/catalog requests start no subscription.
- `pane_owner_test.go`: a pane moving between lanes (history, one undo, CLI `moved_from`), the read-time latest-lane rule on hand-made shared data, and `lanes.pane-one-lane=false`.
- `page_test.go`, `cmd/o-story/stories/lanes/*.json`: monogatari fixtures and the four L4, two L8, two project, a name-tone opt-out, two status-filter (`filter-state`, `state-filter-setting`), an agent (`agent-working`), an association-to-focus (`focus-pane`) and two state-description (`state-description`, `state-description-off`) stories, plus tree/catalog mounting, opt-outs, fixed-clock durations, ordering, pane chooser failures, focus and yank checks. Data and identity are isolated; every external command is fake.
- `Makefile`: bounded Go build/test and coordinator race gate.

The app owns domain state and persistence; released ochazuke owns the CLI, catalog, rights gate and UI. No family-library modifications or local module replacements are required.

Compared with Vim: domain operations have no Vim counterpart. Navigation/folding/search reuse ochazuke; the read-only viewer uses its scroll window with j/k, gg/G and ctrl+d/ctrl+u binding rows (eight-line half-page movement). See README for help tags and differences.

Mounted extension rows include live snapshots. Released ochazuke v0.72.1 has no persistent external page subscription hook; hosted reader lifetimes and per-run tones in Markdown detail require general framework capabilities. No app-specific daemon or host workaround is introduced.
